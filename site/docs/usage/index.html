Searching

You don't need to type loxx first: type at your normal prompt.

zsh: suggestions as you type

Type what you want to do, or part of a command, and stop typing for a moment. Matching commands appear under the line:

~/code $ undo my last commit 
  git reset --soft HEAD~1  ~/code/shop · 3 days ago
  git revert HEAD  ~/code/api · 2 weeks ago
  • Nothing is chosen until you press ↓. Then ↑ ↓ move, and Enter puts the command in your prompt, ready to edit. It never runs by itself.
  • Enter without ↓ runs what you typed, as usual. Keep typing to close the list.
  • Commands containing your words show after about 0.3 s. Commands that do what you described follow after about 1 s: that search uses the language model, so it only runs once you've stopped typing, never on every key.
  • Lines shorter than 3 characters and lines starting with a space get no suggestions.

bash: describe it and press Enter

bash can't react to each key, so type what you want to do and press Enter. If the first word isn't a command, the search list opens with your words already typed in, instead of command not found. The command you pick replaces your line, ready to edit or run; it never runs by itself. Esc keeps your line, and Enter on it again runs it as typed. Real commands run as always.

The search list

Type loxx with no arguments to open the full search list right under your prompt, with filters.

loxx ❯ undo last commit 
▸ git reset --soft HEAD~1  ~/code/shop · 3 days ago · 2× ✓
  git revert HEAD  ~/code/api · 2 weeks ago ✓
  git commit --amend  ~/code/shop · 1 day ago · 6× ✓
  git log --oneline -5  imported
filter: all (Tab) · ↑↓ · Enter use · Esc cancel

Keys

KeyWhat it does
TypeSearch. Exact matches show at once, matches by meaning a moment later.
↑ ↓Move through the list.
TabSwitch the filter (see below). Shift+Tab goes back.
EnterPut the command in your prompt, ready to edit or run.
Esc or Ctrl+CClose without choosing.

With an empty search, the list shows your most recent commands.

Reading a result

Each line shows the command, then the folder it ran in, when it last ran, how many times it ran (14×), and whether it worked: ✓ for success, ✗ for a failure. Commands loaded from your old history say “imported”. A command that spans several lines is shown on one line, with ↵ marking the line breaks.

Filters

Tab cycles through:

FilterShows
allEverything.
this dirCommands run in this folder. Inside a git repository: anywhere in the same repository.
this sessionCommands run in this terminal window or tab.
failedCommands whose last run failed.

Keyword and meaning

Every search runs two ways at once and merges the results:

  • Keyword: commands containing all the words you typed. Good for names you remember: kubectl port-forward.
  • Meaning: commands whose purpose is closest to what you typed, even with no words in common. “expose my service locally” finds kubectl port-forward too.

Search by meaning always shows the closest matches, even when none of them is a good match.

From scripts and other tools

loxx search prints matches instead of opening the list:

loxx search --limit 3 compress a folder
tar -czvf backup.tar.gz ~/Documents
    ~ · 2 weeks ago · exit 0 · 1 run

Running the program directly as ~/.local/bin/loxx (without the shell hook) opens the list and prints the chosen command, so you can use it in your own scripts.
